# Смеч 0.5. Аудит изменений и проверки

Дата: 07.11.2026. Относится к сборке `Smech-v0.5.zip`.

## Проверенные проблемы и принятые решения

1. **Невозможно быстро сопоставить распознанный объём с оригиналом.** В версии 0.4 хранилась ссылка на страницу, но не координаты каждой строки. Добавлено `rowBbox`, локальная отрисовка PDFium, полупрозрачная подсветка строки. Для существующей позиции хранится SHA-256; просмотр после повторной загрузки выполняется только при совпадении хеша.
2. **Спецификация не отделена от расчётной потребности.** Добавлен самостоятельный список спецификаций, импорт с выбором листа и столбцов, ручная проверка, раздельное хранение. Никаких значений стоимости из спецификации в смету не переносится.
3. **Риск подбора неверных аналогов.** Автоматический подбор по смысловой близости запрещён. Сравнение строгое: нормализованное название и единица. «м2» и «м²» специально не объявляются равными автоматически.
4. **Риск незаметного изменения согласованной суммы.** Решения относятся к конкретному серверному снимку с SHA-256 и ревизией. При изменении рабочего проекта прежнее согласование получает статус устаревшего.
5. **Риск самосогласования.** Инженерное заключение может вынести только назначенный редактор, который не создавал данный снимок. Утверждение руководителя разрешено только владельцу после положительного инженерного решения.
6. **Риск утверждения с отсутствующими данными.** Если движок сообщает о блокирующих замечаниях, положительное решение невозможно. При расхождениях импортированной спецификации от потребности каждый согласующий должен описать основание исключения; без мотивировки API отклоняет одобрение.
7. **Защита хранилища.** Добавлена валидация новых полей спецификации и местоположения исходной строки, ограничения файлов и номеров страниц. Новая SQL-таблица решений имеет уникальный ключ на этап и снимок.
8. **Миграция схемы.** Подготовлена миграция 0002. Проверено обновление чистой SQLite с 0001 до 0002; существующую рабочую PostgreSQL не меняли.

## Фактическое тестирование

- `pytest`: 45 успешных тестов, в том числе 12 новых сценариев/параметризованных проверок версии 0.5.
- `alembic upgrade head`: применены 0001 и 0002 к временной базе SQLite, таблица `smech_review_decisions` создана.
- `node --check`: все три основных клиентских скрипта проходят синтаксическую проверку.
- API `source-page`: подтверждены PNG-ответ, идентификатор SHA-256 и отказ некорректных координат.
- Chromium, моковые ответы API: импорт трёх материалов, отображение сравнения, открытие подсвеченной строки PDF и её повторная сверка из сохранённой ВОР; ошибок JS нет.
- Реальное соединение Chromium с `127.0.0.1` отклонено ограничением тестовой среды, поэтому результаты браузерного теста **не равнозначны** эксплуатации на настоящем сервере.

## Остающиеся эксплуатационные риски

1. PDF/OCR непредсказуем на некачественных сканах и разных российских формах; обязателен контроль инженерного работника.
2. Не проверены длительные сеансы и конкурентная работа десятков пользователей, PostgreSQL под нагрузкой, отказоустойчивость и восстановление из резервных копий.
3. Исходные PDF не сохраняются: при последующей проверке их нужно предоставить повторно; SHA-256 лишь проверяет побайтовое совпадение.
4. Согласование — внутренняя запись, а не электронная подпись по Федеральному закону № 63-ФЗ.
5. Нормативные сметные базы РФ отсутствуют. Коммерческий расчёт нельзя выдавать за нормативную строительную смету.
6. Решения по материалам не учитывают аналоги, производственные упаковки, транспортную кратность, складские остатки и гарантированные сроки поставки.
7. Не проводились полноценный внешний security-аудит, проверка всех транзитивных лицензий и ревизия промышленных секретов.

## Приоритет следующих задач

Первая — пилот на трёх настоящих ВОР и спецификациях с ручной сверкой каждой позиции. Вторая — политика хранения первичных документов и резервного копирования. Третья — тестовый PostgreSQL с HTTPS и журналом доступа, оценка производительности. Четвёртая — интеграция прайс-листов поставщиков с указанием их дат и сроков действия, а также проверка материалов по проектным чертежам без самостоятельного угадывания объёмов.
