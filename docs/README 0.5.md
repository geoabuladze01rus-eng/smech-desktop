# Смеч 0.5 — контроль ВОР, спецификации материалов, согласование

Дата сборки: 7 ноября 2026 года. Программа предназначена для коммерческой калькуляции строительных работ российским подрядчиком; это **не** сметная документация по ФСНБ/ГЭСН. Все нормативы, расценки и исходные количества должны быть предоставлены и проверены пользователем.

## Что реализовано

**Базовые функции 0.1–0.4:** объекты и ведомости работ, импорт XLSX/CSV/TSV, PDF и локальный OCR сканов, привязки материальных ресурсов с зафиксированными ценами, оплата бригад, коммерческий расчёт, НДС, экспорт, история версий, дополнительный серверный режим с логинами и доступами.

**Новое в 0.5:**

1. Для каждой импортированной строки PDF сохраняется `sourceRef`: SHA-256 оригинала, номер страницы/таблицы/строки и координаты строки. В окне импорта кнопку **Показать** можно использовать для просмотра исходной PDF-страницы с подсвеченной строкой. В сохранённой ВОР кнопка **PDF** позволяет сделать то же после повторного выбора оригинального файла и проверки его SHA-256. Файл не сохраняется в проекте.
2. Раздел **Спецификации**: импорт XLSX/CSV/TSV и электронных PDF; сканы через опциональный локальный Tesseract OCR. Пользователь назначает столбцы, выбирает строки и подтверждает импорт. Спецификации хранятся отдельно от стоимости материалов. Сопоставление с потребностью выполняется только по точному нормализованному имени и единице измерения; отображаются совпадения, дефицит, избыток, строки без пары. Автоматического пересчёта единиц или подбора аналогов нет.
3. В Excel-экспорте добавлены страницы **Спецификация** и **Сверка**.
4. В дополнительном **серверном рабочем пространстве** доступен двухэтапный маршрут согласования **архивной** версии: инженер (назначенный редактор объекта) → руководитель (владелец объекта). Решения хранятся в отдельной таблице SQL, привязаны к хешу и ревизии снимка. Редактировать зафиксированное решение через API нельзя. Изменение расчёта требует создания новой архивной версии и нового согласования. Одобрение с блокирующими замечаниями невозможно. Если загруженная спецификация не совпадает с потребностью, одобрение возможно только с текстовой мотивировкой расхождений от каждого согласующего.
5. Добавлена миграция Alembic `0002_review_decisions.py`, расширены тесты.

Согласование является **внутренней записью действий пользователей**, а не квалифицированной электронной подписью и не удостоверяет юридическую подлинность документа.

## Запуск локально

Нужны Python 3.11+ и pip. Из распакованной директории:

```bash
python -m pip install -r requirements-pdf.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

В браузере открыть `http://127.0.0.1:8000`. По умолчанию проекты остаются в `localStorage` **конкретного браузера**. Для сохранения регулярно выгружайте JSON. Это не многопользовательское безопасное хранение.

Для OCR дополнительно установить локальную программу **Tesseract** и русский языковой пакет `rus`, затем:

```bash
python -m pip install -r requirements-ocr.txt
```

Обработка PDF происходит локально на сервере, где запущен Python. Размер PDF не более 15 МБ, до 40 страниц, при OCR не более 10 страниц на загрузку. Для PDF со сканами без чётких границ таблицы автоматическое распознавание может быть недоступно. Проверяйте каждую импортированную строку по оригиналу.

## Дополнительное рабочее пространство и согласование

Проводите эти действия **только в тестовой базе**, а не в рабочем сервере без резервной копии.

```bash
python -m pip install -r requirements-postgres.txt
# Укажите отдельную тестовую базу PostgreSQL (либо отдельную SQLite для испытаний)
export SMECH_DATABASE_URL='sqlite:////абсолютный/путь/к/test-smech.db'
alembic upgrade head
export SMECH_ENABLE_WORKSPACE=1
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Для Windows переменные задаются через `set` (cmd) или `$env:...` (PowerShell). Создайте первого администратора в интерфейсе, добавьте сотрудника с ролью редактора на объект и создайте серверный снимок расчёта. Инженер (не автор снимка) согласует его через раздел **Согласование**, затем владелец утверждает ту же версию. Отказ требует указания причин. При новых изменениях создаётся новый снимок.

**Нельзя выставлять сервер в интернет** без TLS, управления секретами, резервного копирования, независимой проверки безопасности и контроля доступа. Версия 0.5 пока не проходила нагрузочные испытания PostgreSQL или аудит на проникновение.

## Тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --check static/app.js
node --check static/workspace.js
node --check static/advanced.js
```

При подготовке выпуска: **45 автоматических тестов пройдены**. Проверены API и миграции на чистой SQLite, PDF-отрисовка строки, согласование с правами доступа и расхождения спецификаций. В изолированном Chromium с подставленными ответами API проверены сценарии импорта спецификации, предварительного просмотра PDF и повторного открытия исходного файла без ошибок JavaScript. Сквозной браузерный тест с **реальным HTTP-сервером** здесь недоступен из-за ограничений сети тестового браузера; испытание на настоящем ПК необходимо.

## Структура

- `engine.py`, `specifications.py`: расчётное ядро и сверка потребности со спецификацией.
- `pdfio.py`, `excelio.py`, `app.py`: распознавание PDF, таблиц и HTTP API.
- `static/app.js`, `static/advanced.js`, `static/workspace.js`: интерфейс и серверный режим.
- `workspace_store.py`, `workspace_api.py`, `migrations`: учётные записи, роли, SQL и согласование.
- `tests`: автоматические проверки.
- `examples`: изображения учебного интерфейса.
- `Пример спецификации.csv`, `Пример ВОР для PDF 0.4.pdf`: учебные исходные документы с вымышленными значениями.

## Оставшиеся ограничения

- Профессиональная проверка на реальных ведомостях заказчиков, многостраничных сканах, спецификациях и чертежах ещё не проведена.
- PDF-распознавание ищет таблицы, но **не выполняет снятие геометрических объёмов с чертежей**. Не реализованы IFC/BIM и автоматическое определение расхода материалов по типу работы.
- ФСНБ-2022, ГЭСН, ФГИС ЦС, официальный расчёт по методикам Минстроя, прайс-листы поставщиков не подключены.
- Решения согласования не имеют КЭП, не заменяют подписи на сметах и не удостоверяют их юридическую силу.
- Перед коммерческим развёртыванием требуется отдельная проверка лицензий всех зависимостей, TLS, политика хранения исходных PDF, резервное копирование и нагрузочный тест PostgreSQL.

Дальнейший этап: работа с комплектами проектной документации и источниками поставщиков, контроль редакций чертежей и тестовые расчёты на реальных объектах с участием инженера-сметчика.
