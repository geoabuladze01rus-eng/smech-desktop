# Смеч 0.3 — ведомость объёмов работ и коммерческий расчёт СМР

Версия 0.3, 6 ноября 2026 года. Российский коммерческий калькулятор для строительных подрядчиков. **Не является программой формирования официальной сметы по ФСНБ/ГЭСН**: российские нормативные базы и расчёты по Методике № 421/пр не подключены.

## Реализовано

- Объекты, ВОР, разделы, коды, источники объёмов; импорт XLSX/CSV/TSV с сопоставлением столбцов. Объёмы из PDF, сканов и BIM/IFC пока не читаются.
- Материалы с нормой расхода, потерями, закупочной ценой и фиксированным снимком цены на позиции ВОР; сдельная оплата СМР.
- Структура коммерческой себестоимости (материалы, оплата исполнителям, начисления, доставка, техника, накладные, наценка, отдельный режим НДС), экспорт Excel/CSV/JSON.
- Локальный режим хранения в браузере (как в 0.2).
- Дополнительный многопользовательский режим: собственная база SQLAlchemy (SQLite для тестов, PostgreSQL для серверной установки), авторизация, защита паролей Argon2, HTTP-only cookie-сеансы, CSRF, пользовательский справочник, роли по объекту (владелец, редактор, просмотр).
- Оптимистичная блокировка: устаревшая версия объекта или справочника не может перезаписать новую. Сохраняются редакции объекта, сравнение изменений цен и журнал действий, отдельно можно создавать серверные архивные снимки расчётов. Удалённые объекты можно восстановить из корзины владельца.
- Ручной перенос локальных объектов/материалов в рабочее пространство без перезаписи существующих идентификаторов. При ошибке сохранения браузер предлагает скачать JSON и не обновляет сервер молча.
- Начальная схема Alembic `0001`. Для последующих изменений схемы необходимы новые миграции и резервные копии.

## Быстрый запуск (Windows/Linux/macOS)

Требуется Python 3.11+ (тестировался 3.13). В распакованной папке:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`. Это **только локальный режим**, доступ к данным только в этом браузере. Для него достаточно `start.sh` / `start.bat` из папки.

### Тестовый режим с отдельной базой

Запустите `start-workspace.sh` (Linux/macOS) или `start-workspace.bat` (Windows), либо выполните:

```bash
# Linux/macOS
export SMECH_ENABLE_WORKSPACE=1
export SMECH_DATABASE_URL='sqlite:///./smech-workspace.db'
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте **Настройки и копии → Настроить**, создайте первого администратора (логин латиницей, пароль от 12 символов). Первоначальная регистрация разрешена только при локальном подключении; в другом контуре заранее определите `SMECH_SETUP_TOKEN` и соблюдайте HTTPS. Администратор создаёт логины сотрудников. Владелец объекта выдаёт роли «Редактор» или «Просмотр» по существующему логину. Для возврата в автономный режим используется кнопка «Локальный режим». **Локальные проекты автоматически не отправляются на сервер.** Ручной перенос выполняется в настройках после подтверждения.

SQLite предназначена для разработки и проверки на одном компьютере. Для нескольких одновременно работающих сотрудников рекомендуется PostgreSQL.

### PostgreSQL: подготовленный, но не развёрнутый вариант

Потребуется существующий PostgreSQL с отдельным пользователем и базой данных. Ни одна реальная внешняя база в ходе разработки не изменялась.

```bash
python -m pip install -r requirements-postgres.txt
export SMECH_ENABLE_WORKSPACE=1
export SMECH_DATABASE_URL='postgresql+psycopg://smech_user:CHANGE_ME@localhost:5432/smech'
alembic upgrade head
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

**Не храните настоящий пароль БД в файлах исходного кода или истории команд.** В примере `CHANGE_ME` — обозначение, а не настоящий пароль. Используйте переменные окружения и хранилище секретов. Запуск для внешних пользователей требует HTTPS через обратный прокси, явного `SMECH_ALLOWED_HOSTS`, установки `SMECH_SECURE_COOKIES=1`, корректной обработки заголовков прокси, резервирования, мониторинга и проверки безопасности; без этих условий не открывайте приложение в интернет.

### Миграции

На новой базе `alembic upgrade head` устанавливает первоначальную схему. Локальная SQLite-схема также создаётся автоматически при первом включении рабочего пространства; если она была создана без Alembic, не запускайте `upgrade head` поверх неё без `alembic stamp 0001` после предварительной проверки совпадения схемы и резервной копии. Последующие изменения структуры должны идти новыми Alembic-ревизиями, не через `create_all`.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --check static/app.js
node --check static/workspace.js
```

Проверены 27 автоматических тестов; отдельная проверка интерфейса на Chromium с тестовым API-посредником: создание администратора, вход, создание объекта, серверное сохранение без ошибок JavaScript. Исходная Excel-ведомость 0.2 по-прежнему обрабатывается тем же модулем импорта. Миграция `0001` успешно применялась к пустой тестовой SQLite-базе. **Живой PostgreSQL и реальные корпоративные ВОР разных заказчиков пока не испытывались.**

## Изоляция и конфиденциальность

- В локальном режиме проекты — в localStorage браузера; если очистить данные браузера, их можно потерять. Резервные JSON-файлы сохраняйте самостоятельно.
- В режиме сервера данные сохраняются в PostgreSQL либо SQLite в JSON-полях. Шифрование на уровне приложения не реализовано. Используйте защищённые диски, безопасные резервные копии и приватную инфраструктуру.
- Не пересылайте производственные документы на сторонние сервисы OCR без согласования. Приложение не вызывает внешние ИИ API.
- Журнал показывает изменения, но хеш SHA-256 не заменяет электронную подпись и юридически значимую систему электронного документооборота.
- Учётные записи не имеют публичной самостоятельной регистрации; первый администратор создаётся локально или по отдельному ключу. Реализация ограничения попыток входа рассчитана на один процесс и требует внешнего rate limiting при масштабировании.
- Не объявляйте архив безусловно неизменяемым: операция изменения снимков не доступна через обычный API, но администратор БД технически может менять данные.

## Известные ограничения

Отсутствуют автоматическое извлечение ВОР из PDF и IFC, централизованный бэкап серверной базы, TLS-прокси/production-деплой, обмен файлами между сотрудниками, подтверждение расчёта руководителем, самостоятельное восстановление пароля и полноценное слияние параллельных изменений. При конфликте редакций необходимо экспортировать незаписанные изменения в JSON и решить конфликт вручную. Поддержка `.xls` не реализована. Вводимые пользователем цены, потери и ставки **не являются подтверждёнными рыночными или нормативными данными**.

## Структура исходников

- `app.py` — FastAPI, маршруты расчёта, XLSX/CSV, заголовки безопасности.
- `engine.py` — детерминированная математика Decimal, проверки полноты ВОР.
- `excelio.py` — импорт/экспорт XLSX без обращения к облачным сервисам.
- `workspace_store.py` — SQLAlchemy-модели, контроль изменений, права и снимки.
- `workspace_api.py` — API авторизации, проектов, архивов, прав и миграции локальных данных.
- `static/workspace.js` — UI входа, серверного сохранения, ролей, журнала и конфликтов.
- `static/app.js` и `static/styles.css` — интерфейс и локальный режим версии 0.2.
- `migrations/` — Alembic миграция начальной схемы.
- `tests/` — тесты ядра, импорта, API и прав доступа.

Серверный режим можно включить на собственной приватной инфраструктуре без подписок SaaS, но нужна настройка и ответственное администрирование.
