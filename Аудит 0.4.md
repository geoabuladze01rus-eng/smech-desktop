# «Смеч» 0.4 — технический аудит PDF и дальнейший план

Дата: 07.11.2026. Проверка исходного кода локальной версии 0.3 и обновлений 0.4. Настоящий отчёт не является независимым аудитом информационной безопасности или заключением о соблюдении лицензий.

## Найденные риски и исправления

| Проблема | Исправление в 0.4 | Остаточный риск |
| --- | --- | --- |
| Файлы PDF не импортировались | Обработка текстовых PDF табличным парсером | Сложные макеты, колонтитулы, вложенные таблицы и чертежи могут не читаться |
| Сканы нельзя было прочитать | Опциональное локальное OCR Tesseract + поиск линий ячеек | В OCR ошибки в цифрах и единицах, особенно «м²»; ручная проверка обязательна |
| Не прослеживался источник распознанного объёма | В каждой строке: PDF, страница, таблица, строка, SHA-256 файла | Исходный PDF не архивируется автоматически и должен храниться у заказчика/подрядчика |
| Риск молчаливого массового импорта | Предварительный просмотр, редактирование, выбор строк, отдельное подтверждение | Оператор всё ещё может подтвердить неправильную строку; автоматический контроль по чертежам отсутствует |
| Итоги и некорректные объёмы могли попасть в ВОР | Проверка обязательных полей, положительного количества, попытка исключить «Итого», «Всего», «Сумма» | Названия итогов отличаются; проверяющий должен контролировать полноту/правильность строк |
| Риск лицензионных ограничений AGPL при коммерциализации | От PyMuPDF перешли к pdfplumber и pypdfium2 | Лицензии транзитивных библиотек и бинарной сборки требуют отдельного анализа перед продажей |
| Ошибка распознавания ряда сканированных ячеек из-за координат | Исправлена работа с шириной изображения и контуром таблицы; резервный OCR пустых ячеек | Метод рассчитан на достаточно хорошо видимую прямоугольную сетку |
| Неконтролируемая нагрузка | Лимиты 15 МБ, 40 страниц, 10 страниц OCR, 5000 строк, 80 столбцов, ограничение времени OCR | Для серверного SaaS нужны общие quotas, вынос OCR в отдельный воркер и мониторинг ресурсоёмкости |

## Результаты воспроизводимых проверок

- **33 Python-теста прошли**; среди них 6 PDF-тестов, остальные — регрессии версий 0.2–0.3.
- `node --check` проходит для `static/app.js` и `static/workspace.js`.
- Учебная русскоязычная цифровая ведомость: 2 страницы, общая таблица из 7 строк с заголовком; источник для продолжения на стр. 2 подтверждён.
- Тестовый скан: PDF с изображениями без текстового слоя, распознан локально при включённом OCR. Проверка потребовала осторожности с единицей площади («м²» может распознаваться как «м?» или «м2»).
- Тест в изолированном Chromium с контролируемым тестовым ответом API: создание объекта, распознавание полей, запрет пустого подтверждения, перенос ровно 5 рабочих строк, сохранение ссылок на страницы PDF; ошибок JavaScript нет. Настоящий доступ Chromium к локальному серверу был заблокирован политикой среды, поэтому это **не полноценный сетевой E2E-тест**. При этом серверные API отдельно проверены через FastAPI `TestClient`.
- Проверки на реальных корпоративных PDF, схеме PostgreSQL под нагрузкой и на публичном домене не выполнялись.

## Что необходимо до версии для платящих клиентов

1. Собрать репрезентативную тестовую выборку (не менее 20 разных ВОР: цифровые PDF, сканы, табличные и нетабличные чертежи, XLSX); для каждой строки сделать эталон с единицей, объёмом, листом и расчётом ошибки OCR. Нельзя объявлять процент точности без такой выборки.
2. Добавить наглядное сравнение строки с фрагментом исходной страницы, хранить первичный документ в защищённом хранилище с versioning и проверкой SHA-256, разграничением прав и журналом доступа.
3. Добавить построчный workflow согласования: «не проверено» → «проверено сметчиком» → «одобрено руководителем», с именем/датой и запретом незавершённых коммерческих предложений.
4. Добавить импорт спецификаций материалов, связку с ВОР и сверку с закупочным прайс-листом, отдельные версии цен и источники. Не подставлять нормы без подтверждённой нормативной базы/договора.
5. Настроить отдельный воркер OCR, очередь заданий, тайм-аут, защиту от перегрузки, резервные копии и развертывание PostgreSQL в приватном облаке. Выполнить внешний аудит уязвимостей.
6. До коммерческого распространения проверить полный список лицензий компонентов. Для ФСНБ/ГЭСН/ФГИС ЦС отдельно определить правомерность получения и актуализации нормативных данных.

## Короткий технологический вывод

PDF-модуль построен на pdfplumber (таблицы/текст) и pypdfium2 + Tesseract (сканы). У этой архитектуры ниже потенциальные лицензионные риски для закрытого коммерческого продукта, чем у прямого включения PyMuPDF под AGPL; юридическая проверка всё равно необходима. Испытания подтвердили работоспособность на искусственных примерах, но не точность на ведомостях заказчиков.
