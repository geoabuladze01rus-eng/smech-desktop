# «Смеч» 0.3 — отчёт о технической ревизии

Дата: 06.11.2026. Проверка выполнена по имеющемуся исходному коду версии 0.2 и автоматизированным сценариям новой версии. Это внутреннее заключение разработчика, а не независимый аудит информационной безопасности.

## Существенные риски и фактические решения

| Категория | Риск до 0.3 | Исправление | Что пока осталось |
| --- | --- | --- | --- |
| Разделение пользователей | Общие локальные данные нельзя контролировать по ролям | Логины, owner/editor/viewer, контроль на сервере | Нет внешнего SSO/2FA и централизованного управления организациями |
| Гонка редакций | Второй пользователь мог без следа затереть объёмы | `expectedRevision` и транзакционный отказ при несовпадении | Нет трёхстороннего слияния изменений |
| Происхождение изменений | Неизвестно, кто менял объёмы, цены и расходы | Автор, дата, ревизия, сравнение позиций и цены материала | Нужен расширенный построчный журнал основания изменения |
| Архив | Ограниченная история localStorage | Серверные снимки с hash, неизменяемый через API архив | Нет защищённого внешнего WORM/подписей и регламентного резервирования |
| Удаление | Удалённый объект терялся из интерфейса | Мягкое удаление и восстановление владельцем | Не реализованы сроки хранения/юридическая политика удаления |
| Риски миграции | Старые привязки материалов зависели от текущего каталога | Копия цены, даты, источника и единицы при импорте | Если в старом каталоге уже утрачена цена, восстановить её автоматически нельзя |
| Неполная ВОР | Отсутствие признака необходимости материалов не блокировало готовность | Строгая проверка булева поля | Необходим инженерный контроль каждой позиции |
| Формат денежных данных | Дробные значения с запятой могли обходить лимит разрядности | Единые проверки десятичных разделителей | Для бухгалтерской отчётности нужна отдельная сверка сумм/НДС |
| Инфраструктура | Нет постоянной базы | SQLAlchemy SQLite для тестов, схема PostgreSQL и Alembic | Производственная PostgreSQL-инсталляция не испытана |
| Безопасность | Нет аутентификации/CSRF | Argon2, HttpOnly SameSite cookie, CSRF, TLS-требование для удалённого доступа | Двухфакторная авторизация и внешний rate-limit пока не реализованы |

## Границы испытаний

- 27 Python-тестов прошли. Включены ролевые запреты, конфликт ревизий, защита от частичных сохранений, замороженные цены, импорт legacy, архив, корзина и откат на владельца.
- JavaScript прошёл проверку синтаксиса Node 22.
- Первичная миграция `0001` на SQLite выполнилась успешно.
- Проверка интерфейса в Chromium использовала контролируемый тестовый API-посредник вследствие ограничений сети браузера в рабочей среде. Это **не полноценное эксплуатационное испытание внешнего сервера**.
- Нет тестовой PostgreSQL-инсталляции и набора реальных XLSX/PDF ВОР заказчиков; нельзя заявлять производственную готовность.

## Требования до промышленного запуска

1. Протестировать PostgreSQL с несколькими одновременными сессиями, миграцией, восстановлением из резервной копии и отрицательными сценариями доступа.
2. Развернуть защищённый контур: TLS, секреты, шифрование дисков, мониторинг, временное ограничение сессий, регулярный бэкап и проверка восстановления.
3. Провести внешний аудит API/зависимостей, настройку rate-limit на инфраструктурном уровне и политику персональных данных.
4. Проверить коммерческий расчёт на настоящих ВОР и прайсах минимум нескольких независимых объектов. Убедиться, что единицы измерения сопоставимы, нормы обоснованы, начисления и режим НДС определены правильно.
5. В следующей версии реализовать PDF-распознавание (например Docling) с обязательным подтверждением объёмов человеком и привязкой каждой позиции к листу исходника. Не использовать автоматически распознанные цифры как подтверждённые.

Сроки и цена создания полноценной SaaS-платформы этим документом не оцениваются.
